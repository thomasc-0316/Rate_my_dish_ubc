# Image Generation Setup Guide

This document outlines what needs to be configured in Supabase for AI-generated dish images to work.

## Prerequisites Checklist

### ✅ 1. Database Schema Update
- [x] Add `image_url text` column to the `dishes` table
  ```sql
  ALTER TABLE dishes ADD COLUMN image_url text;
  ```

### ✅ 2. Supabase Storage Bucket
- [x] Create a public storage bucket named `dish-images`

**Steps to create:**
1. Go to Supabase Dashboard → Storage
2. Click "Create a new bucket"
3. Name: `dish-images`
4. Make it **Public** (important!)
5. Click "Create bucket"

**Storage bucket permissions:**
The bucket must be publicly accessible so that image URLs work on the frontend. The scraper uses the service role key to upload images.

---

## Required Environment Variables for Edge Function

The `scraper` Edge Function needs these environment variables to be set:

| Variable | Where to Find | Purpose |
|----------|---------------|---------|
| `URL` | Dashboard → Settings → API → Project URL | Supabase project URL |
| `SERVICE_ROLE_KEY` | Dashboard → Settings → API → Service Role Key | Admin access to write to database and storage |

**Note:** These are automatically available in Edge Functions when deployed to Supabase. No manual configuration needed.

---

## What the Image Generation Does

When the scraper runs:

1. **Fetches menu data** from Nutrislice for all dining halls
2. **For each unique dish:**
   - Generates an AI image using Pollinations.ai (free, no API key needed)
   - Creates a prompt: `"A delicious {dish name}, {description}, professional food photography, appetizing, high quality"`
   - Downloads the generated image
   - Uploads it to `dish-images` bucket in Supabase Storage
   - Saves the public URL to the `image_url` column in the database

3. **Uses parallel processing** to generate all images simultaneously for faster scraping

## Deployment Checklist

### Option A: Deploy via Git Integration
If Supabase is connected to your GitHub repo:
1. Push the updated code to GitHub
2. Supabase will automatically deploy the new Edge Function

### Option B: Deploy via Supabase CLI
```bash
# Login to Supabase
supabase login

# Link to your project
supabase link --project-ref YOUR_PROJECT_REF

# Deploy the function
supabase functions deploy scraper
```

### Option C: Deploy via Dashboard
1. Go to Supabase Dashboard → Edge Functions
2. Find the `scraper` function
3. Update the code manually (copy from `supabase/functions/scraper/index.ts`)
4. Deploy

## Expected Behavior

When the scraper runs successfully, you should see:
- Console logs: `"Generating images for X unique dishes..."`
- For each dish: `"Generating image for 'Dish Name'..."`
- Success messages: `"Successfully generated and uploaded image for 'Dish Name'"`
- Images appearing in Storage → `dish-images` bucket
- Database `dishes` table populated with `image_url` values
- Frontend displaying AI-generated images for each dish

## Troubleshooting

### Images not appearing?
- Check that `dish-images` bucket is **public**
- Verify the scraper Edge Function has been deployed with the latest code
- Check Edge Function logs for errors

### Storage errors?
- Ensure the service role key is valid
- Verify the bucket exists and is named exactly `dish-images`
- Check bucket permissions are set to public

### Pollinations.ai errors?
- The service is free and requires no API key
- Errors are logged but don't stop the scraper - it will continue with `null` image URLs
- Images can be regenerated by running the scraper again
